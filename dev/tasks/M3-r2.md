# M3-r2 작업 지시서 — 검수 루프와 게이트 (2라운드)

## 목표
M3-r1 결과물을 검수 지적에 맞게 고친다. 범위·spec 절·공통 규칙은 `dev/tasks/M3-r1.md`와 같다. 검수 전문은 `dev/reviews/M3-r1.md`.

## 고칠 지적

### R-001 — 게이트 문제 문자열에 원인을 구체적으로
- 게이트 지적은 다음 작업 라운드의 AI가 읽고 고친다. `src/engine/gates.ts`의 모든 문제 문자열에 문제를 일으킨 id나 값을 넣는다.
  - 예: `TODO id 형식 오류: DEV-1, X-002`, `id 중복: DEV-003`, `레인 id 형식 오류: z`, `레인 id 중복: a`
- G3은 빠진 대상과 남는 항목을 나눠 적는다. 예: `items에 없는 대상: DEV-002 / 대상이 아닌 항목: DEV-009`.
- G9의 증거 누락 메시지는 해당 시나리오·탐색·결함을 식별할 수 있게 적는다(id, 탐색은 title).
- 테스트: 대표 사례(G1 형식, G1 중복, G3, G9 증거 누락)의 메시지에 해당 id가 들어 있는지 확인한다.

### R-002 — G4는 worktree 밖 증거를 실패시킨다
- 절대 경로나 worktree 밖으로 나가는 경로(`..`, 심볼릭 링크로 빠져나가는 경로 포함)는 `worktree 밖 증거: <path>`로 실패시킨다. G9의 qaDir 검사와 같은 방식이다.
- 테스트: `/etc/hostname`, `../x`를 증거로 넣으면 실패하는지 확인한다.

### R-003 — G5가 `spawnProcess`를 쓴다
- `src/clients/spawn.ts`: `stderrPath`가 `stdoutPath`와 같으면 파일을 한 번만 열어 같은 fd를 stdout·stderr에 쓴다.
- `gateTests`는 직접 spawn하지 않고 `spawnProcess({ command: 'sh', args: ['-c', testCommand], stdin: '', stdoutPath: logPath, stderrPath: logPath, ... })`를 쓴다. 이렇게 해야 실행 중인 테스트도 `killAllChildren`의 대상이 된다.
- 테스트: 같은 경로일 때 stdout과 stderr가 한 파일에 모두 남는지 확인한다. 기존 G5와 spawn 테스트는 그대로 통과해야 한다.

1. 위 3건이 해결되고 M3-r1의 완료 기준을 계속 만족한다.
2. `node --test test/*.test.ts` 전체 통과, `npx tsc --noEmit` 오류 0, 120자 초과 줄 없음.
