# F001-r1 작업 지시서 — 통합 fix의 새 시나리오 lane

## 목표
fix 기획을 승인하고 새 시나리오를 plan.json에 붙일 때 lane을 spec §5.3대로 정한다. 병렬 레인(a~h)이면 그 레인, `main`과 `integration`이면 null이다. 지금은 integration fix의 새 시나리오에 `integration`이 들어간다(dev/reviews/M8-r1.md F-001). spec.md는 수정하지 않는다.

## 바꿀 것
- `src/engine/pipeline.ts`의 FIX_PLANNING 승인 처리에서 새 시나리오의 lane 결정 조건(`lane.id === 'main' ? null : lane.id`)을 `main`·`integration` 모두 null이 되게 고친다.
- 테스트: 통합 QA 실패 → integration fix로 새 회귀 시나리오가 붙는 기존 병렬 테스트에서, 새 시나리오의 lane이 null인지 확인한다. 병렬 레인 fix의 새 시나리오는 그 레인 id인지도 확인한다(기존 테스트가 이미 확인하면 그대로 둔다).
