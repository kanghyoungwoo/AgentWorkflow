# M7-r1 작업 지시서 — 예약(at), 조회 명령, cleanup, qa-runtime setup

## 목표
남은 CLI 명령을 모두 구현한다: `status`, `logs`, `list`, `watch`, `cleanup`, `qa-runtime setup`. 한도 소진 시 resume을 `at`으로 예약·해제하는 기능도 만든다. Master 스킬과 README는 M8이다.

## 따를 spec 절
§4.3(timeline·events·raw·meta), §5.8(scheduledResume, Pending.resetAt), §6.4(예약 규칙), §8.5 공통 절차 2(resume 시 atrm), §9 첫 문단(`--json` 지원 명령), §9.1 status·logs·list·watch·cleanup·qa-runtime 행, §9.2, §11.

## 만들 것

### 1. `src/schedule.ts` (§9.2)
- `atTimestamp(date)`: 로컬 시각 `CCYYMMDDhhmm`(`at -t` 형식). 초가 0이 아니면 다음 분으로 올린다.
- `parseAtJobId(stderr)`: `job <N> at …`에서 N을 꺼내고, 없으면 null.
- `scheduleResume({ runId, workspace, at: Date })`:
  - 셸 명령 `'<node>' '<repo>/bin/agent-workflow.mjs' resume <run-id> --workspace '<ws>' >> '<ws>/ai-log/<run-id>/scheduled-resume.log' 2>&1`을 stdin으로 `at -t <시각>`에 넘긴다.
  - 경로는 작은따옴표로 인용하고, 값 안의 `'`는 `'\''`로 바꾼다. node는 `process.execPath`, repo는 도구 루트다.
  - 반환값은 `{ atJobId, at: ISO }`이고, `at`이 없거나 실패하면 null이다. 실행기는 테스트에서 주입할 수 있게 한다.
- `cancelResume(atJobId)`: `atrm <id>`를 실행하고, 실패(이미 실행됨 등)는 무시한다.
- `atAvailable()`: `at` 실행 파일이 있고 `systemctl is-active atd`가 `active`면 true.

### 2. 예약을 run/resume에 연결 (`src/commands/run.ts`)
- run·resume의 파이프라인이 끝난 직후, `rate_limited` Pending 중 `resetAt`이 있는 것이 있으면 **가장 늦은 resetAt + 2분**에 1건만 예약한다(§6.4).
  - 성공하면 `state.scheduledResume`에 기록하고 `schedule` 이벤트를 남긴다.
  - at을 쓸 수 없거나 resetAt이 하나도 없으면 예약하지 않고 그 사실을 `schedule` 이벤트로 남긴다(§9.2 마지막 줄). 종료 코드는 그대로다.
- resume을 시작할 때 `state.scheduledResume`이 있으면 `cancelResume` 후 null로 만든다(지금은 null로만 만듦).
- 예약으로 실행된 resume이 다시 한도에 걸리면 같은 규칙으로 다시 예약한다(별도 처리 불필요, 위 규칙의 결과).

### 3. 공용 이벤트 출력 형식
- run, resume, watch는 같은 함수로 이벤트 한 줄을 출력한다. 형식은 `<로컬 YYYY-MM-DD HH:mm:ss> <lane|run> <stage|-> <role|-> <type> <verdict|-> <message>`이다. 지금 run.ts의 ISO UTC 출력을 이것으로 바꾼다(§4.3, C13).

### 4. `src/commands/inspect.ts` — status, logs, list, watch (§9.1)
- 공통: `<ws>/ai-log/<run-id>/state.json`이 없으면 "런 없음"과 종료 코드 2. run-id 형식 검증.
- **status**
  - `current`: 단계, status, mode, parallel, 마지막 종료 코드, 런 브랜치·worktree, 레인 표(id, phase, status, qaAttempt, qaRollbacks), Pending 목록(id, lane, stage, kind, exitCode, summary, resetAt), 예약을 사람용 한국어로 보여 준다.
  - `timeline`: timeline.md 원문.
  - `decisions`: events 중 type이 author·gate·tests·review·qa이면서 verdict가 있는 것을 `| 시각 | 레인 | 단계 | 역할 | 판정 | 내용 |` 표로 보여 준다(설계도 슬라이드 11).
  - `plan`: plan.md.
  - `todo`: `02-development/*/todo.md`를 레인 이름 제목과 함께 모두 보여 준다.
  - `qa`: 가장 최근 report.md(파일 mtime 기준, 모든 레인과 integration 중)를 경로와 함께 보여 준다.
  - 파일이 없으면 "아직 없음"을 출력하고 종료 코드 0.
  - `--json`: `{ runId, mode, parallel, status, stage, lastExitCode, runBranch, runWorktree, lanes[], pending[], scheduledResume, lastEvents }`. lanes 원소는 `{ id, phase, status, branch, worktree, qaAttempt, qaRollbacks }`, lastEvents는 최근 10개 RunEvent다. `--json`이면 view와 관계없이 이 형식이다.
- **logs**
  - 인자 없음: raw `*.meta.json`을 seq 순서로 표로 보여 준다(seq, lane, stage, role, round는 파일 이름에서, exitCode·durationMs는 meta에서).
  - `--seq N`: 그 호출의 prompt.md, 최종 출력, stderr 끝 100줄을 보여 준다. 최종 출력은 codex면 last.json, claude면 out.json의 structured_output(없으면 원문)이다. 없는 seq면 2.
  - `--json`: 같은 정보를 배열이나 객체로 낸다.
- **list**: `ai-log/*/state.json`을 모아 run-id, mode, status, stage, lastExitCode, updatedAt을 updatedAt 내림차순으로 보여 준다. `--json` 지원. ai-log가 없으면 빈 목록이다.
- **watch**:
  - 기존 이벤트를 모두 출력한 뒤 2초마다 새 이벤트만 출력한다. 간격은 테스트에서 주입할 수 있게 한다.
  - status가 RUNNING이 아니면 남은 이벤트를 출력하고 종료한다(종료 코드 = lastExitCode ?? 0).
  - RUNNING인데 run.lock이 없거나 PID가 죽었으면 "실행 프로세스가 없습니다"를 알리고 1로 종료한다.

### 5. `src/commands/cleanup.ts` (§9.1)
- `<run-id>` 또는 `--finished`(status DONE인 모든 런)를 받는다.
- run.lock이 살아 있으면 거부한다(2). DONE이 아닌 런은 `--force`가 없으면 거부한다(2).
- 지우는 것:
  - 레인 worktree와 레인 브랜치(`aw/<run-id>-lane-*`)
  - 런 worktree
  - `.aw/worktrees/<run-id>` 디렉터리
  - `git worktree prune`
  - 예약 작업(`cancelResume` 후 scheduledResume null)
- **런 브랜치와 ai-log는 남긴다.**
- `git.ts`의 `worktreeRemove`에 `force` 옵션을 추가한다(`--force`일 때만). 이미 없는 worktree는 건너뛴다.
- 지운 항목을 출력하고 이벤트를 남긴다(type `info`는 없으므로 기존 type 중 `commit`·`merge`는 쓰지 말고 RunEvent type에 `cleanup`을 추가한다. types.ts와 §4.3 목록에 추가하는 것은 허용).

### 6. `src/commands/qa-runtime.ts` (§9.1)
- `qa-runtime setup [--slots] [--base-port]`의 동작:
  1. 도구의 playwright CLI로 `install chromium`을 실행한다(`node <repo>/node_modules/playwright/cli.js install chromium`, 출력은 그대로 보여 줌).
  2. 포트 base..base+slots-1이 모두 비어 있는지 확인한다(app-runner의 포트 검사 재사용). 하나라도 사용 중이면 그 포트를 알리고 2.
  3. `~/.agent-workflow/qa-runtime.json`에 `{ basePort, slots }`를 쓴다.
- 홈 디렉터리와 설치 실행기는 테스트에서 주입할 수 있게 한다.

### 7. cli.ts에 핸들러 등록
status, logs, list, watch, cleanup, qa-runtime setup을 등록한다. 이제 "아직 구현되지 않은 명령"은 없어야 한다. 관련 테스트도 고친다.
