# M1-r1 작업 지시서 — 골격

## 목표
`agent-workflow`의 골격을 만든다: 프로젝트 설정, 공용 타입, CLI 인자 파싱·검증, 설정 로더, request.md 파서, state/lock, ai-log(runlog), git 헬퍼. 실제 명령 동작(doctor, run 엔진, 에이전트 호출 등)은 이후 마일스톤이므로 **만들지 않는다**.

## 따를 spec 절
§0.1 A1, §1, §2.4(git 헬퍼에 필요한 부분), §3(파일 배치), §4.1~§4.3, §5.1, §5.2~§5.8(타입), §8.3·§8.4(종료 코드), §9 첫 문단과 §9.1(인자와 검증만), §11(하지 않을 것).

## 이미 준비된 것
- `node_modules`에 ajv 8.20.0, playwright 1.63.0, typescript 7.0.2, @types/node 24.19.1이 설치되어 있다(네트워크 없이 사용 가능). TypeScript 7.0.2에서 아래 tsconfig 옵션이 동작하는 것을 확인했다.

## 만들 파일

### 프로젝트 설정
- `package.json`: name `agent-workflow`, version `0.1.0`, `"private": true`, `"type": "module"`, `bin: { "agent-workflow": "bin/agent-workflow.mjs" }`, `engines.node: ">=22.18"`, dependencies `ajv: "8.20.0"`, `playwright: "1.63.0"`, devDependencies `typescript: "7.0.2"`, `@types/node: "24.19.1"`(모두 정확한 버전), scripts `test: "node --test test/*.test.ts"`, `typecheck: "tsc --noEmit"`.
- `tsconfig.json`: `target: esnext`, `module`/`moduleResolution: nodenext`, `strict: true`, `noEmit: true`, `erasableSyntaxOnly: true`, `allowImportingTsExtensions: true`, `verbatimModuleSyntax: true`, `types: ["node"]`, include `src`, `test`.
- `.gitignore`: `node_modules/`.
- `bin/agent-workflow.mjs`: `#!/usr/bin/env node`. `src/cli.ts`의 `main(process.argv.slice(2))`를 await하고 반환값을 `process.exitCode`로 설정한다.

### `src/types.ts`
§4.2 `WorkspaceConfig`(기본값이 채워진 최종 형태)와 `Role`, §4.3 `RunEvent`, §5.2~§5.8의 모든 타입을 spec과 1:1로 옮긴다(`Blocker`, `BlockerKind`, `Response`, `Issue`, `PlanAuthorOutput`, `Todo`, `QaScenario`, `Lane`, `Plan`, `Evidence`, `ReviewOutput`, `DevAuthorOutput`, `QaReport`, `WikiAuthorOutput`, `RunState`, `LoopState`, `LaneState`, `Pending`). 종료 코드는 `as const` 객체(`OK 0, FAIL 1, USAGE 2, NEEDS_ANSWER 20, NEEDS_USER 21, RATE_LIMITED 22`)와 그 값 타입으로 둔다(`enum` 금지).

### `src/config.ts` + `schemas/config.schema.json` (§4.2)
- `loadConfig(workspace)`: `<workspace>/agent-workflow.json`을 읽어 검증하고 기본값을 합친 `{ config, found }`를 돌려준다. 파일이 없으면 전부 기본값이고 `found: false`. JSON 문법 오류나 스키마 위반은 이유를 담은 오류를 던진다(CLI에서 종료 코드 2로 쓸 수 있게, 메시지는 한국어).
- 기본값: `setupCommand null`, `testCommand null`, `app null`, `wikiDir "docs/wiki"`, roles(`planningAuthor`·`devAuthor`·`wikiAuthor` → codex, `planningReviewer`·`devReviewer`·`wikiReviewer`·`qa` → claude, model·effort null), limits(maxReviewRounds 5, sameIssueLimit 2, maxQaRollbacks 3, maxLanes 3, stepTimeoutMin 45), `app.startTimeoutSec` 90.
- 병합: roles는 역할별·필드별로, limits는 필드별로 합친다. `app`이 객체면 `startCommand`, `readyUrl`은 필수이고 `startTimeoutSec`만 생략 가능하다.
- 스키마(draft-07, ajv 기본 클래스): 모든 객체 `additionalProperties: false`, 모든 필드 선택. 문자열 명령·URL·wikiDir은 빈 문자열 금지. role 키는 7개 역할만, `client` ∈ codex|claude, `effort` ∈ low|medium|high|xhigh|null, `model` string|null. limits는 1 이상 정수이고 `maxLanes`는 1~8(레인 id가 a~h이므로).

### `src/store/request.ts` (§5.1)
- `parseRequest(text)` → 성공 시 `{ title, goal, requirements: {id, text}[], raw }`, 실패 시 한국어 오류 목록. CRLF를 처리한다.
- 검증: 첫 `# ` 제목이 있어야 함. `## 요구사항` 섹션 안에서 `^- (REQ-\d{3}): (.+)$` 줄이 1개 이상이고 id가 중복되지 않아야 함(섹션 밖 REQ 줄은 무시). `## 스펙 외 범위` 섹션이 있어야 함. `goal`은 `## 목표` 섹션 본문(앞뒤 공백 제거, 없으면 "").

### `src/store/state.ts` (§4.3, §5.8)
- `newLoopState()`: round 0, judgedRounds 0, issueStreak {}, lastOutput null, lastIssues [], reviewIssues [], stageBase null, decisions [], grant null.
- `newRunState({ runId, workspace, mode, parallel, baseRef, sinceRef, runBranch, runWorktree })`: status RUNNING, stage는 wiki 모드면 `WIKI` 아니면 `PLANNING`, planning은 새 LoopState, wiki는 wiki 모드일 때만 새 LoopState(아니면 null), lanes [], integration null, pending [], lastExitCode null, scheduledResume null, seq 0, setupDone false.
- `readState(runDir)` / `writeState(runDir, state)`: 쓰기는 `updatedAt`(ISO 8601 UTC)을 갱신하고 임시 파일에 쓴 뒤 rename한다.
- run.lock(§8.5 1단계): `acquireLock(runDir)`는 파일을 배타적으로 만들어 현재 PID를 쓴다. 이미 있으면 PID가 살아 있는지 확인해서(`process.kill(pid, 0)`, EPERM도 살아 있음으로 봄) 살아 있으면 "이미 실행 중" 오류, 죽었거나 내용이 잘못됐으면 넘겨받는다. `releaseLock(runDir)`는 자기 PID일 때만 지운다. `readLock(runDir)` → `{ pid, alive } | null`(이후 watch에서 씀).

### `src/store/runlog.ts` (§4.3)
- `makeRunId(name, now = new Date())` → 로컬 시각 `YYYYMMDD_HHMMSS_<name>`. `isValidSlug(name)` → `/^[a-z0-9-]+$/`.
- 경로 함수: run 디렉터리(`<ws>/ai-log/<run-id>`), `01-planning/round-NN.<kind>.json`, `01-planning/fix/<lane>-<N>/round-NN.<kind>.json`, `02-development/<lane>/round-NN.<kind>.<ext>`와 `02-development/<lane>/fix-<N>/round-NN.<kind>.<ext>`, `03-qa/<lane>/attempt-NN/`, `04-wiki/round-NN.<kind>.json`, raw 파일 접두사 `raw/NNNN-<lane>-<stage>-<role>-rNN`(lane null이면 `run`). NN은 2자리, NNNN은 4자리 0 채움(넘치면 그대로 늘어남).
- `initRunDir(workspace, runId, requestText | null)`: `ai-log/<run-id>/`와 `raw/`를 만들고 requestText가 있으면 `00-request/request.md`에 쓴다. run 디렉터리가 이미 있으면 오류(덮어쓰지 않음).
- 이벤트: `appendEvent(runDir, event)`는 events.jsonl에 한 줄을 붙이고 timeline.md에 한 행을 붙인다(파일이 없으면 헤더부터). `readEvents(runDir)`, `renderTimeline(events)`(순수 함수: 헤더 `| 시각 | 레인 | 단계 | 역할 | 판정 | 내용 |`, 구분선, 이벤트 행). 행 형식은 §4.3대로: 시각은 `at`을 로컬 `YYYY-MM-DD HH:mm:ss`로, null은 `-`, 내용의 `|`는 `\|`, 줄바꿈은 공백. **appendEvent로 쌓은 timeline.md는 `renderTimeline(readEvents())`와 정확히 같아야 한다.**

### `src/git.ts` (§2.4)
셸 없이 `execFile`로 git을 부르는 async 헬퍼. 실패하면 명령과 stderr를 담은 오류를 던진다. 오케스트레이터 커밋은 모두 `git -c commit.gpgsign=false commit --no-verify`.
- 조회: `isGitRepo`, `hasCommit`, `headSha`, `resolveRef(ref)`(없으면 null), `statusPorcelain`, `diffNameOnly(from, to = "HEAD")`, `isAncestor(a, b)`.
- `addExcludes(workspace, patterns)`: `git rev-parse --git-common-dir` 기준 `info/exclude`에 없는 줄만 붙인다(디렉터리·파일이 없으면 만듦).
- `worktreeAdd(workspace, path, branch, startPoint)`, `worktreeRemove(workspace, path)`, `branchDelete(workspace, branch)`.
- `commitAll(cwd, message)`: `git add -A` 후 변경이 없으면 null, 있으면 커밋하고 새 HEAD SHA.
- `squash(cwd, stageBase, message)`: `reset --soft <stageBase>` 후 커밋, 새 HEAD SHA(변경이 없으면 null).
- `restore(cwd, sha)`: `reset --hard <sha>` + `clean -fd`.
- `merge(cwd, branch)`: `merge --no-ff --no-edit`(커밋 옵션은 위와 같음). 충돌이면 충돌 파일 목록을 모은 뒤 `merge --abort`하고 `{ ok: false, conflicts }`, 성공이면 `{ ok: true }`.

### `src/cli.ts` (§9, §9.1, §8.4)
- `parseCommandLine(argv)`: 순수 함수. `util.parseArgs`(strict)로 명령별 인자를 파싱·검증해 `{ ok: true, command, ... }` 또는 `{ ok: false, error }`(한국어)를 돌려준다. 명령: `doctor`, `run`, `resume`, `status`, `logs`, `list`, `watch`, `cleanup`, `qa-runtime setup`.
- 공통: `--workspace <path>`(기본 cwd, 절대 경로로 변환). `--json`은 doctor·status·list·logs에서만 허용.
- 검증 규칙(§9.1):
  - run: `--mode` 필수(plan|full|wiki). `--request-file`은 plan·full에서 필수, wiki에서 선택. `--parallel`은 wiki에서 금지. `--since`는 wiki에서 필수, 그 외에는 금지. `--name`은 `isValidSlug`, 기본 `run`.
  - resume: run-id 위치 인자 정확히 1개. `--answer <text>`(빈 문자열 금지), `--lane <id>`, `--grant network|full`, `--mode full`(full만 허용).
  - status: run-id 1개, `--view current|timeline|decisions|plan|todo|qa`(기본 current). logs: run-id 1개, `--seq`는 1 이상 정수. list: 위치 인자 없음. watch: run-id 1개.
  - cleanup: run-id 1개와 `--finished` 중 정확히 하나, `[--force]`.
  - `qa-runtime setup`: 하위 명령 `setup` 필수. `--slots`는 1~32 정수(기본 4), `--base-port`는 1~65535 정수(기본 4100).
  - 명령이 없거나 모르는 명령이면 사용법을 담은 오류.
- `main(argv)`: 파싱이 실패하면 stderr에 오류와 사용법을 쓰고 2를 돌려준다. 성공하면 명령 핸들러 표에서 찾아 실행한다. **M1에서는 핸들러 표를 비워 두고**, 등록되지 않은 명령은 "아직 구현되지 않은 명령입니다: <command>"를 stderr에 쓰고 2를 돌려준다.
