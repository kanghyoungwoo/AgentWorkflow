# M2-r1 작업 지시서 — 클라이언트 1 (spawn, claude 어댑터, rate-limit, doctor)

## 목표
에이전트 CLI를 하위 프로세스로 안전하게 실행하는 계층과 claude 어댑터, 사용량 한도 감지, `doctor` 명령을 만든다. 검수 루프·게이트·파이프라인은 M3 이후이므로 만들지 않는다. codex 어댑터는 M5다.

## 따를 spec 절
§4.3(raw 파일, meta.json), §6.1, §6.2(claude 열), §6.3(claude 줄), §6.4, §9.1 `doctor` 행, §12(V3, V4), §13 M2, §11.

## 만들 파일

### `src/clients/spawn.ts` (§6.1)
- `resolveExecutable(name)`: PATH에서 실행 파일을 찾는다(없으면 null).
- `spawnProcess({ command, args, cwd, stdin, timeoutMs, stdoutPath, stderrPath, env? })` → `{ exitCode: number | null, signal, timedOut, durationMs }`.
  - `shell: false`, `detached: true`. stdin으로 문자열을 쓰고 닫는다. stdout·stderr는 지정한 파일로 그대로 저장한다.
  - 타임아웃이면 프로세스 그룹 전체(`process.kill(-pid, ...)`)에 SIGTERM, 5초 뒤에도 남아 있으면 SIGKILL.
  - `killProcessGroup(pid)`(SIGTERM → 5초 → SIGKILL)는 export한다(M4의 앱 종료, SIGINT 처리에서 다시 쓴다).
  - 실행 중인 자식의 pid 집합을 모듈 수준에서 추적하고 `killAllChildren()`을 export한다(§8.3 SIGINT/SIGTERM 처리용, 핸들러 연결은 M4).

### `src/clients/index.ts`
```ts
type Profile = "readonly" | "write" | "qa";
type AgentCall = {
  role: Role; profile: Profile; grant: "network" | "full" | null;
  cwd: string; prompt: string; schema: object;   // JSON Schema 객체
  qaDir: string | null;                          // qa 프로필일 때만
  model: string | null; effort: "low" | "medium" | "high" | "xhigh" | null;
  timeoutMs: number;
  rawPrefix: string;                             // runlog.rawPrefix 결과(확장자 없음)
};
type AgentResult = {
  output: unknown | null;        // 추출한 JSON(검증은 호출자, M3), 추출 실패면 null
  exitCode: number | null; timedOut: boolean; durationMs: number;
  rateLimited: boolean; resetAt: string | null;  // ISO
  sessionId: string | null;
  error: string | null;          // 추출 실패·비정상 종료 이유(한국어 한 줄)
};
interface AgentClient { run(call: AgentCall): Promise<AgentResult> }
```
- `profileFor(role)`: planningAuthor·모든 Reviewer → readonly, devAuthor·wikiAuthor → write, qa → qa.
- `clientFor(config, role)`: 설정의 client에 맞는 AgentClient. codex는 M5 전까지 "codex 어댑터는 아직 없음" 오류를 던지는 것으로 둔다.

### `src/clients/claude.ts` (§6.2, §6.3)
- `buildClaudeArgs(call, sessionId)`: 순수 함수. §6.3 순서대로 `-p --output-format json --json-schema <한 줄 JSON> --session-id <uuid>`, 프로필 인자, `--strict-mcp-config --disable-slash-commands`, 있으면 `--model`, `--effort`.
  - readonly: `--permission-mode dontAsk --allowedTools "Read Grep Glob Bash(git diff *) Bash(git log *) Bash(git show *) Bash(git status *)" --disallowedTools "Edit Write NotebookEdit"` (각 값은 argv 원소 하나)
  - write: `--permission-mode acceptEdits --allowedTools "Read Grep Glob Edit Write Bash"`, grant full이면 `--permission-mode bypassPermissions`(acceptEdits 대신). grant network는 인자 변화 없음.
  - qa: `--permission-mode dontAsk --allowedTools "Read Grep Glob Write Edit Bash" --add-dir <qaDir>`.
- `extractClaudeResult(stdout)`: 순수 함수. JSON의 `structured_output`이 있으면 그것, 없으면 `result` 문자열을 JSON.parse, 둘 다 안 되면 null과 이유. `is_error: true`도 실패로 본다.
- `claudeClient.run(call)`: cwd = `call.cwd`, 세션 id는 `randomUUID()`. raw 파일 `<rawPrefix>.prompt.md`, `.out.json`(stdout 원문), `.stderr.log`, `.meta.json`(§4.3 `{ client, args(프롬프트 제외), cwd, exitCode, durationMs, sessionId, rateLimited }`)을 쓴다. 비정상 종료 또는 추출 실패면 rate-limit 검사(§6.4)를 한다.
- claude 실행 파일을 찾지 못하면 오류 결과(exitCode null, error)를 돌려준다.

### `src/clients/rate-limit.ts` (§6.4)
- `detectRateLimit(text)`: §6.4 정규식.
- `parseResetTime(text, now = new Date())` → Date | null. §6.4의 4개 패턴을 순서대로. 2·4번은 로컬 시각의 다음 도래 시점(이미 지났으면 다음 날), 3번은 now + 시간·분.
- 샘플 메시지 단위 테스트(예: `Claude AI usage limit reached|1791234567`, `5-hour limit reached ∙ resets 3pm`, `You've hit your usage limit. Try again in 2 hours 13 minutes.`, `try again at 3:05 PM`, 매치 없음).

### `src/commands/doctor.ts` (§9.1 doctor, §12, §13 끝 문단)
- 검사 항목과 판정(`ok` | `warn` | `fail`, 한국어 detail):
  - Node ≥ 22.18, git 존재
  - workspace가 커밋 1개 이상인 git 저장소(아니면 fail), 커밋 안 된 변경(warn)
  - agent-workflow.json 스키마(위반 fail, 파일 없음 warn)
  - **설정된 역할이 실제로 쓰는 클라이언트만**: 경로와 버전(`--version`), 로그인(`codex login status` 종료 코드 0, `claude auth status` JSON의 `loggedIn`)
  - `app`이 있으면 도구의 playwright로 chromium headless 기동(실패 fail)
  - `at` 명령 존재와 `systemctl is-active atd`(실패하면 warn만)
- `--deep`(토큰 소모): claude를 쓰는 역할이 있을 때만 임시 git 저장소에서 claude 어댑터로 실제 호출.
  - V3: readonly 프로필, 스키마 `{ ok: boolean }`(strict 형식)로 "Return {\"ok\": true}." → `structured_output`(또는 result)이 스키마에 맞으면 ok.
  - V4: readonly 프로필로 임시 저장소에 파일 쓰기를 지시 → 파일이 생기지 않고 `git status --porcelain`이 비어 있으면 ok. 같은 호출에서 `git diff HEAD` 실행 결과를 `{ ok: boolean, diffRan: boolean }`로 보고하게 해서 diffRan이 false면 warn("readonly 프로필에서 git diff가 허용되지 않음").
  - V1(codex)은 "M5에서 확인" warn.
- 출력: 사람용 한국어 표, `--json`이면 `{ ok, checks: [{ name, status, detail }] }`. fail이 하나라도 있으면 종료 코드 2, 아니면 0.
- `src/cli.ts`의 핸들러 표에 doctor를 등록한다.
- 외부 명령 실행은 주입 가능하게(테스트에서 가짜 실행기 사용) 만든다.

## 테스트 (오프라인, 실제 claude/codex 호출 금지)
- `spawn.test.ts`: stdin 전달과 stdout·stderr 파일 저장, 종료 코드, 타임아웃 시 손자 프로세스까지 종료(예: node 스크립트가 sleep하는 자식을 띄움), 없는 실행 파일 resolve → null.

- `rate-limit.test.ts`: 위 샘플, 고정 now 기준.
- `doctor.test.ts`: 가짜 실행기로 역할별 필수 클라이언트(모두 claude면 codex 검사 안 함), 로그인 안 됨 → fail, atd 비활성 → warn, 종료 코드, --json 형태.
