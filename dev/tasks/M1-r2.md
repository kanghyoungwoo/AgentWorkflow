# M1-r2 작업 지시서 — 골격 (2라운드)

## 목표
M1-r1 결과물을 검수 지적에 맞게 고친다. 범위와 따를 spec 절은 `dev/tasks/M1-r1.md`와 같다. 검수 전문은 `dev/reviews/M1-r1.md`에 있다.

## 고칠 지적

### R-001 — `src/store/request.ts` 하위 제목 처리
- 현재 `###` 이하 하위 제목이 `##` 섹션을 끝낸다. 그래서 `## 요구사항` 안의 하위 제목 아래 REQ 줄이 오류 없이 빠지고, `## 목표`도 하위 제목에서 잘린다.
- `# `(H1)와 `## `(H2) 제목만 섹션을 바꾸고, `###` 이하 제목은 현재 섹션에 속하게 한다. 목표 본문에는 하위 제목 줄도 포함한다.
- 테스트 추가: 아래 요청에서 REQ-001·REQ-002가 모두 추출되고 goal에 "배경 문장"이 들어 있어야 한다.
  ```
  # 작업
  ## 목표
  목표 문장
  ### 배경
  배경 문장
  ## 요구사항
  - REQ-001: 첫 번째
  ### 화면
  - REQ-002: 하위 제목 아래
  ## 스펙 외 범위
  - 없음
  ```

### R-002 — `src/git.ts` 경로 목록의 이스케이프
- git 기본 설정(`core.quotePath=true`)에서는 `docs/wiki/검색.md`가 `"docs/wiki/\352\262\200\354\203\211.md"`처럼 나온다. 이 결과는 이후 게이트(G4·G7·G8)에서 실제 경로와 비교된다.
- `diffNameOnly`와 `merge`의 충돌 목록은 `-z` 출력(NUL 구분)을 나눠 디스크의 실제 경로를 그대로 돌려준다.
- 테스트 추가: 한글 파일 이름(예: `docs/wiki/검색.md`)과 공백이 든 파일 이름(예: `a b.txt`)이 `diffNameOnly`에 그대로 나오는지 확인한다. 한글 파일 이름이 충돌 목록에 그대로 나오는지도 확인한다.

### R-003 — `schemas/config.schema.json` 중복
- 역할 항목 스키마가 7번 복사되어 있다. `definitions.role` 하나를 두고 7개 역할 속성이 `$ref`로 가리키게 한다. 기존 config 테스트는 그대로 통과해야 한다.

### R-004 — 줄 길이와 한 줄 한 문장
- 동작은 바꾸지 말고 형식만 고친다. `src/`와 `test/`의 모든 줄을 **120자 이하**로 하고, `;`로 이어 붙인 여러 문장은 한 줄에 하나씩 쓴다.
- 짧은 guard(`if (...) return x;`)나 `for (...) assert...` 한 줄은 120자 안이면 괜찮다.
- 확인 명령: `awk 'length($0) > 120 { print FILENAME ":" FNR }' src/*.ts src/store/*.ts test/*.ts`의 출력이 비어 있어야 한다.

## 완료 기준
1. 위 4건이 모두 해결되고, M1-r1 지시서의 완료 기준을 계속 만족한다.
2. `node --test test/*.test.ts` 전체 통과(새 테스트 포함), `npx tsc --noEmit` 오류 0.
3. 위 awk 확인 명령의 출력이 비어 있다.
