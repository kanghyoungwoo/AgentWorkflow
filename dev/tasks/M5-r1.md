# M5-r1 작업 지시서 — 클라이언트 2 (codex 어댑터)

## 목표
codex 어댑터를 만들어 `client: "codex"` 역할이 실제로 동작하게 하고, `doctor --deep`에 V1을 넣는다. 병렬 레인(M6), 예약과 조회 명령(M7)은 만들지 않는다.

## 따를 spec 절
§4.3(raw: out.jsonl, last.json, meta.json), §6.1, §6.2(codex 열), §6.3(codex 줄과 cwd), §6.4, §9.1 doctor, §12 V1, §13 M5, §11.

## 만들 파일·바꿀 파일

### `src/clients/codex.ts` (§6.2, §6.3)
- `buildCodexArgs(call, schemaPath, lastPath)`: 순수 함수. 순서는 `exec --json -C <cwd> <프로필> --output-schema <schemaPath> -o <lastPath> [-m <model>] [-c model_reasoning_effort=<effort>] -`.
  - readonly: `-s read-only`
  - write: `-s workspace-write`. grant network면 `-c sandbox_workspace_write.network_access=true`를 더한다. grant full이면 `-s` 대신 `--dangerously-bypass-approvals-and-sandbox`를 쓴다.
  - qa: `-s workspace-write`(cwd는 호출자가 qaDir로 준다, M4 stages가 이미 그렇게 함)
- `codexClient.run(call)`:
  - `<rawPrefix>.schema.json`에 `call.schema`를 쓰고 그 절대 경로를 `--output-schema`에 넘긴다. AgentCall은 스키마 객체를 들고 있고, 호출마다 쓴 스키마를 raw에 남기기 위해서다.
  - 프롬프트는 stdin으로 넘긴다. raw 파일은 `.prompt.md`, `.out.jsonl`(stdout), `.last.json`(`-o`), `.stderr.log`, `.meta.json`(§4.3, client `codex`, args에는 프롬프트를 넣지 않음).
  - 결과: `last.json`을 JSON.parse한다. 파일이 없거나 비었거나 파싱에 실패하면 output null과 이유를 남긴다.
  - sessionId는 out.jsonl의 첫 `thread.started` 이벤트의 `thread_id`이고, 없으면 null이다.
  - 비정상 종료·타임아웃·추출 실패면 stdout과 stderr로 rate-limit 검사(§6.4)를 한다. 동작 규약은 claude 어댑터와 같다(M2).
  - codex 실행 파일을 찾지 못하면 오류 결과를 낸다.
- `src/clients/index.ts`의 `clientFor`: codex면 `codexClient`.

### `src/commands/doctor.ts`
- `--deep`에서 codex를 쓰는 역할이 있으면 V1을 실제로 확인한다. 임시 git 저장소에서 codex 어댑터로 readonly 호출하고, 스키마는 `{ ok: boolean }` strict, 프롬프트는 "Return {"ok": true}."다. 출력이 스키마에 맞으면 ok, 아니면 fail(error·exitCode 포함).
- codex를 쓰는 역할이 없으면 V1 검사를 하지 않는다(지금의 "M5에서 확인" warn은 없앤다).
- deep 호출용 클라이언트를 의존성으로 주입할 수 있게 한다(claude·codex 각각).

## 테스트 (오프라인, 실제 codex/claude 호출 금지)
- `codex.test.ts`:
  - 프로필 × grant 명령줄(readonly, write, write+network, write+full, qa)과 model/effort 유무.
  - 가짜 `codex` 실행 파일(임시 디렉터리의 node 스크립트, PATH 앞에 둠)로 다음을 확인한다.
    - stdin 수신, `-o` 파일 쓰기, JSONL 출력(thread.started 포함)
    - run이 raw 6종(prompt, schema, out.jsonl, last.json, stderr, meta)을 쓰는지
    - output과 sessionId 추출
    - last.json이 없거나 깨졌을 때의 오류
    - 한도 메시지("You've hit your usage limit ... try again in 2 hours 13 minutes")일 때 rateLimited와 resetAt
- `doctor.test.ts`: codex 역할이 있으면 V1을 호출하고 결과에 따라 ok·fail, 없으면 V1 항목이 없는지 확인한다.
