## 지적

### R-001 — `src/store/request.ts:12-14`
- 문제: `###` 이하 하위 제목도 현재 `##` 섹션을 끝낸다. 그래서 `## 요구사항` 안의 `### 화면` 아래 REQ 줄이 **오류 없이 빠지고**, 요청은 유효한 것으로 통과한다. 빠진 REQ는 G1 커버리지 검사에서도 사라지므로 요구사항이 조용히 누락된다. `## 목표`도 하위 제목에서 잘린다.
  재현: `# 작업 / ## 목표 / 목표 문장 / ### 배경 / 배경 문장 / ## 요구사항 / - REQ-001: … / ### 화면 / - REQ-002: … / ## 스펙 외 범위 / - 없음` → requirements가 `[REQ-001]`, goal이 `"목표 문장"`.
- 요구 변경: `# `(H1)와 `## `(H2) 제목만 섹션을 바꾸고, `###` 이하 제목은 현재 섹션에 속하게 한다(목표 본문에는 하위 제목 줄도 포함). 위 재현 케이스를 테스트로 추가한다(REQ-001·REQ-002 모두 추출, goal에 "배경 문장" 포함).

### R-002 — `src/git.ts:24`, `src/git.ts:58`
- 문제: git 기본 설정(`core.quotePath=true`)에서는 비ASCII 경로가 따옴표와 8진수 이스케이프로 출력된다. 확인 결과 `docs/wiki/검색.md`가 `"docs/wiki/\352\262\200\354\203\211.md"`로 나왔다. `diffNameOnly`는 G4·G7·G8에서 근거 파일이나 wiki `docs` 경로와 비교하는 데 쓰인다. 그래서 한글 이름의 파일이 하나만 있어도 게이트가 계속 반려하게 된다. merge 충돌 목록도 같은 문제가 있다.
- 요구 변경: `diffNameOnly`와 merge 충돌 목록은 `-z` 출력(NUL 구분)을 나눠 디스크의 실제 경로를 그대로 돌려준다. 한글 파일 이름과 공백이 든 파일 이름으로 `diffNameOnly` 테스트를 추가하고, 충돌 목록 테스트도 하나 추가한다.

### R-003 — `schemas/config.schema.json:65-253`

- 요구 변경: `definitions.role` 하나를 두고 7개 역할 속성이 `$ref`로 가리키게 한다. 기존 config 테스트는 그대로 통과해야 한다.

### R-004 — `src/`, `test/` 전반 (예: `src/store/state.ts:10` 321자, `src/cli.ts:83` 244자, `src/git.ts` 196자)
- 문제: 한 줄에 여러 문장을 이어 붙여 줄 길이가 최대 321자다. M1은 이후 마일스톤이 따를 "기존 스타일"(AGENTS.md)이 되므로 읽기 어려운 형식이 굳어진다.
- 요구 변경: 동작은 바꾸지 말고 줄만 나눈다. `src/`와 `test/`의 모든 줄을 120자 이하로 하고, `;`로 이어 붙인 여러 문장은 한 줄에 하나씩 쓴다. 짧은 guard(`if (...) return x;`)나 `for (...) assert...` 한 줄은 120자 안이면 괜찮다.
