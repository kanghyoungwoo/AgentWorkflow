## 지적

### R-001 — `src/clients/claude.ts:73`, `src/commands/doctor.ts:76-99`
- 문제: 실패 원인을 버린다.
  - claude.ts:73은 실행 예외를 받아 "Claude 프로세스를 실행할 수 없습니다."로만 바꾸고 원래 메시지를 남기지 않는다.
  - doctor의 V3·V4가 fail일 때 detail에 `result.error`·exitCode가 없다.
  - FAIL(1)을 진단하는 Master(§8.4)와 사람에게 단서가 없다.
- 요구 변경:
  - claude.ts의 예외 메시지를 `error`에 포함한다(예: `Claude 프로세스를 실행할 수 없습니다: <message>`).

### R-002 — `src/commands/doctor.ts:83-102` (지시서의 검사 설계 수정)
- 문제: 파일 쓰기 시도와 `git diff` 실행을 한 프롬프트에 섞었고, 모델의 자기 보고(`diffRan`)에 의존한다. 그래서 실제로는 git diff가 허용되는데도 warn이 나왔다(위 수동 확인).
- 요구 변경: git diff 확인을 V4 쓰기 검사와 분리된 별도 호출로 하고, 모델이 git 명령 없이는 알 수 없는 값으로 판정한다.
  - 준비: 임시 저장소에 무작위 토큰(예: `randomUUID()`)이 든 파일을 커밋한 뒤, 작업 사본에서 그 줄을 지운다. 그러면 토큰은 `git diff`의 `-` 줄에만 남는다.
  - 호출: readonly 프로필, 스키마 `{ token: string }`, 프롬프트는 "Run `git diff HEAD` and return the removed line's text as token."
  - 판정: 반환한 token이 일치하면 ok, 아니면 warn("readonly 프로필에서 git diff 결과를 확인하지 못함"). 검사 이름은 `V4 git diff`.
  - V4 쓰기 검사는 쓰기만 지시하고, 파일 존재·status·HEAD로 판정하는 지금 방식을 유지한다(스키마는 `{ ok: boolean }`).

### R-003 — `src/commands/doctor.ts:5`

- 요구 변경: chromium 기동 함수 안에서 `await import('playwright')`로 필요할 때만 불러온다.
