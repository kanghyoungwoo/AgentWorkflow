## 지적

### R-001 — `src/engine/gates.ts:34-36` 외 (게이트 피드백이 구체적이지 않음)
- 문제: 게이트 지적은 사람이 아니라 다음 작업 라운드의 AI가 읽고 고친다. 그런데 문제를 일으킨 대상을 밝히지 않는다.
  - `'TODO id 형식 오류'`, `'시나리오 id 형식 오류'`, `'id 중복'`, `'레인 id 형식 오류'`, `'레인 id 중복'`, `'items가 대상 항목 집합과 다릅니다.'`, `'증거가 1개 이상 필요합니다.'`(G9) 등이다.
  - 작업 AI가 어디를 고칠지 몰라 라운드를 낭비하고, 같은 GATE id가 반복되면 바로 loop_repeat(sameIssueLimit 2)로 Master를 부르게 된다.
- 요구 변경:
  - 모든 게이트 문제 문자열에 원인 id와 값을 넣는다(예: `TODO id 형식 오류: DEV-1, X-002`, `id 중복: DEV-003`).
  - G3은 빠진 id와 남는 id를 나눠 적는다(예: `items에 없는 대상: DEV-002 / 대상이 아닌 항목: DEV-009`).
  - G9 증거 누락은 해당 시나리오나 결함 id를 적는다.
  - 테스트에서 대표 사례 몇 개는 메시지에 id가 들어 있는지 확인한다.

### R-002 — `src/engine/gates.ts:104-107` (G4의 worktree 밖 증거)
- 문제: 증거 경로를 `resolve(cwd, path)`로 확인하므로 `/etc/hostname`이나 `../x` 같은 worktree 밖 파일도 "존재"로 통과한다. spec §7 G4는 "worktree에 모두 존재"다.
- 요구 변경: 절대 경로나 worktree 밖으로 나가는 경로는 `worktree 밖 증거: <path>`로 실패시킨다(G9의 qaDir 검사와 같은 방식). 테스트를 추가한다.

### R-003 — `src/engine/gates.ts:112-142` (spawn 로직 중복, 자식 추적 누락)
- 문제: G5가 `spawnProcess`(M2)와 같은 detached 실행과 타임아웃 종료 로직을 다시 구현했다. 그 결과 테스트 프로세스가 spawn.ts의 자식 집합에 등록되지 않아, §8.3 SIGINT/SIGTERM 처리(`killAllChildren`)가 실행 중인 testCommand를 종료하지 못한다.
- 요구 변경:
  - G5가 `spawnProcess`를 쓰게 한다(`command: 'sh'`, `args: ['-c', testCommand]`, stdin `''`).
  - stdout과 stderr를 한 로그 파일에 남기려면 `spawnProcess`에서 `stderrPath`를 `stdoutPath`와 같게 줄 수 있도록 한다. 같은 경로면 파일을 한 번만 열어 같은 fd를 쓴다.
  - 기존 spawn 테스트는 계속 통과해야 한다. 같은 경로 사용 테스트를 하나 추가한다.
